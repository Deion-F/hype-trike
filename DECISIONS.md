## 0b. Implementation choices (Claude's defaults; override any time)

| # | Choice | Why |
|---|---|---|
| I.1 | Use **pygame-ce with an asyncio main loop** instead of the `pgzrun.go()` runner. The Wireframe code gets refactored into it. | pygbag needs an `async` main loop that yields to the browser every frame. Pygame Zero's blocking runner doesn't fit that, and pygbag ships pygame-ce, so desktop and web use the same library. This is still the Python + pygbag path (Option A). |
| I.2 | Fixed logic resolution: **360 px tall**, with width set from the screen's aspect ratio (640 on 16:9, about 780 on a 19.5:9 phone) | "Smooth fill" with no stretching and no black bars: wider phones show more track ahead. |
| I.3 | Track column = **80 px** (8 per 640 px view) | Keeps the homage's "8 blocks on screen" rhythm (100 px in 800 px). |
| I.4 | Simulation runs at a **fixed 60 Hz**, deterministic and frame-based | The ghost-rider validator and the CPU rivals run the exact same physics as the player. |
| I.5 | All art and audio are **generated in code** (pixel art drawn with pygame, chiptune synthesized) | Original assets, nothing ripped, no asset pipeline needed. |

## Change history

- 2026-11-13: **Mouse button scheme flipped: the button leans forward in the air** (user). Mid-air the held button now pushes the nose down (winding up: `PRESS_START` 0.35 + `PRESS_GROW` 0.05 of the pitch rate per tick), and released the nose lifts (the drift rate plus `RELEASE_GROW` 0.04 of the pitch rate per tick free, up to `RELEASE_MAX` 0.8; these keep the values tuning pass 4 gave the old `FALL_*`). A button held up the ramp carries straight on into the forward lean at take-off (no re-press), since you leave a ramp nose-up. Doing nothing in the air now lifts the nose, so long jumps need feathering. Setting label: "Click to lean fwd". The `ramp` control bit changed meaning, so recordings made with the first version of the button scheme (earlier today) no longer replay exactly. Sim (`landsim`, 4 seeds, one-button) perfect/rough/crash: novice 21/26/1%, average 49/6/1%, good 76/1/0%, close to the first version after pass 4 (32/24/2, 53/5/1, 82/1/0). The simulated button player now feathers the button to hold the target angle.
- 2026-11-13: Tuning pass 4 (34 live recordings, archived in `recordings/archive/20261113-164421/`, focus: the new mouse "button" scheme). `tools/tuning.py landsim` showed button landings behind keys at the same skill (perfect 50/81% vs 88/97% for average/good, novice rough 27% vs 9%). CONTROL CHANGE: `FALL_GROW` 0.06 -> 0.04 and `FALL_MAX` 1.0 -> 0.8 (config.py): a released button swings the nose down a little more gently, still up to about the key rate. landsim after: button perfect 32/53/82%, novice rough 24%. `PULL_*` left alone (no measurable effect). No difficulty or `MODIFIER_HARDNESS` change; late-heat sims and real runs are too easy (next pass). 163 tests pass. See docs/tuning_log.md.
- 2026-11-13: **Mouse "button" controls are the new default** (user: the anchor-based mouse lean drifted off-screen over ramps in a row; asked for a scheme where you only click and maybe move the mouse). Setting "Mouse controls" (`mouse_steer`): **Click to pull up** (`"button"`, default) / Aim angle / Hold lean / Off. In it the button is throttle/heat on the ground and pulls the nose up in the air, the cursor only picks lanes (hover), and left/right does nothing, so there is no home point to drift. A button still held from the ramp at take-off doesn't pull until it's been released once. The pull winds up (`PULL_START` 0.35 of the pitch rate + `PULL_GROW` 0.05/tick), so a tap is a nudge. Released, the nose falls at the normal drift plus `FALL_GROW` 0.06 of the pitch rate per tick, up to the full rate (`FALL_MAX`), so a long release pushes the nose down as hard as leaning forward, and Steady Nose still softens short releases. Heat is frozen for the whole flight in one-button mode (classic keeps the take-off throttle). Physics sees this as a new control bit `ramp` (recorded last in `CTL_BITS`, so old recordings still replay). Keys and touch are unchanged. Saves on the old default "Aim angle" move over once (`settings_v` 3); "Hold lean" is kept. `tools/tuning.py` gained a simulated button player (`ButtonPilot`, `--controls button|keys`, the default for `sim`/`modsim`) and `landsim`. Also: **respawn past hazards**: a crash recovery with a pit, broken span, drawbridge, barrier, water/lava or a launch ramp into a pit within `RESPAWN_CLEAR_COLS` = 3 tiles ahead respawns just past it (chained, at most `RESPAWN_MAX_SKIP` = 10 tiles), for the player and rivals.

- 2026-11-13: **Audio format fix (laggy/stuttery sound, seen on WSL).** `pygame.init()` opened the mixer at pygame's default 44.1 kHz stereo before `Audio()` could ask for 22,050 Hz mono, so every generated sound was upsampled in Python with nearest-neighbour (harsh) and duplicated to stereo, which doubled the per-frame cost of the incremental music and engine builds. `audio.pre_init()` now runs before `pygame.init()` (`main.App`), so the mixer opens at `SR` mono 16-bit and nothing is resampled. On WSL (WSLg's PulseAudio bridge to Windows) it uses a 1024-sample buffer (46 ms) instead of 512 and sets `PULSE_LATENCY_MSEC=40` unless already set. Override with `HYPE_AUDIO_BUFFER` / `PULSE_LATENCY_MSEC`. Needs `libpulse0` on WSL, or SDL falls back to ALSA and has no device.

Bosses also need a **win** (normal races need top 3 in Valley/Desert, top 2 after) and have stronger rivals: rival levels per depth (0, .15, .32, .68, .92, 1), the boss at the next depth's level. - 2026-11-13: Engine sound rewritten (`hypetrike/audio.py`). The old square-wave pulse loops (38–159 Hz with harmonics up to the top of the range) whined, and each speed step restarted the loop with a hard cut. Now it is a four-stroke single "thumper": 16 pitch steps, firing at 15–82 Hz (~1800–9800 rpm). Each firing is a soft exhaust thump (a ~130–230 Hz bark tone plus filtered noise) with small random changes in timing, strength and tone, so there's no machine-gun repetition, and the loop is low-passed at 12 dB/oct (<1% of energy above 600 Hz). Pitch steps crossfade over 110 ms on two reserved channels, with hysteresis. The loops build a slice per frame and alternate frames with the music builder.
